# 공개 C 코드 실행은 일회성 격리 샌드박스에서만 허용한다

**상태: Proposed.** 이 ADR은 C2 구현을 위한 보안 경계 제안이며 구현 승인 자체가 아니다. 명시적인 사용자·보안 승인이 있기 전에는 C2 실행 코드를 구현하거나 병합하지 않는다.

## Context

정보처리기사 실기 코치는 학습자가 작성한 임의 C 코드를 다룰 수 있다. 현재 제품 계약은 첫 제출 전 정답·힌트·실행 결과를 숨기고, 첫 제출 이후의 교정이 최초 독립 수행 결과를 바꾸지 않으며, 학습자 답안 원문을 장기 학습 이벤트에 저장하지 않는 것이다. 공개 베타의 코드 실행기는 격리·제한·관찰 가능해야 하고, 실행기 장애가 핵심 학습 흐름을 막아서는 안 된다.

C 컴파일과 실행은 단순한 편의 기능이 아니라 공격자 제어 입력을 컴파일러와 운영체제에 전달하는 경계다. 따라서 개인 로컬 검증과 공개 베타의 신뢰 경계를 분리한다.

## Decision

- **개인 로컬 검증**: 개발자 또는 학습자 본인이 소유한 장치에서 본인이 신뢰하는 코드만 제한적으로 실행할 수 있다. 이 경로는 공개 베타의 보안 근거가 아니며, 외부 사용자의 임의 코드를 받는 공유 실행 서비스로 노출하지 않는다.
- **공개 베타**: 컴파일과 실행을 모두 **호스트와 분리된 일회성(disposable) 샌드박스** 안에서 수행한다. 샌드박스는 요청마다 새로 만들고 실행 후 폐기한다.
- 브라우저 전용 실행, 애플리케이션 서버와 같은 프로세스에서의 실행, 격리 없는 `child_process`/호스트 서브프로세스 실행은 공개 베타의 신뢰 경계로 인정하지 않는다.
- 특정 컨테이너·VM·마이크로VM 기술은 이 ADR에서 승인하지 않는다. 향후 구현은 아래 자원·접근 제한을 운영체제 또는 그와 동등한 격리 계층에서 강제해야 한다.

## Threat model

공개 베타에서는 제출 C 소스를 신뢰하지 않는다. 최소한 다음 공격·오동작을 방어 대상으로 본다.

- 악의적이거나 병적인 소스가 컴파일러·어셈블러·링커 등 도구체인의 취약점이나 과도한 자원 사용을 유발하는 경우
- 무한 루프, 과도한 계산, CPU 고갈
- 대규모 할당, 재귀, 메모리 고갈
- 대량 파일 생성·쓰기, 임시 디스크 고갈
- 파일 디스크립터 고갈
- `fork`/프로세스 폭탄과 자식 프로세스 남용
- 호스트 파일시스템, 비밀값, 다른 실행의 파일 읽기
- 외부 네트워크 또는 로컬 네트워크 접근
- stdout/stderr 출력 폭주와 로그 증폭
- 실행 후 프로세스·파일·상태를 남기는 지속성 확보 시도
- 고해상도 실행 시간이나 공유 자원 관찰을 이용한 타이밍/사이드 채널

완전한 사이드 채널 제거는 이 범위에서 보장하지 않는다. 대신 공개 샌드박스에는 사용자 비밀·영구 자격증명·다른 실행의 상태를 넣지 않고, 실행 간 파일시스템과 프로세스를 공유하지 않으며, 외부에 고해상도 호스트 자원 정보를 노출하지 않는다.

## Enforced limits

아래 값은 짧은 시험 코치 C 연습을 위한 **보수적인 초기 기본값**이다. 구현 전 보안 검토에서 더 낮출 수 있지만, 이 ADR 승인 없이 더 높여서는 안 된다.

| 자원                                  |             초기 상한 |
| ------------------------------------- | --------------------: |
| 제출 C 소스 크기                      | UTF-8 기준 **32 KiB** |
| 컴파일 wall-clock                     |               **2초** |
| 실행 wall-clock                       |               **2초** |
| 컴파일+실행 전체 wall-clock 외곽 상한 |               **5초** |
| 컴파일+실행 누적 CPU time             |               **2초** |
| 샌드박스 메모리                       |           **128 MiB** |
| stdout+stderr 합산 출력               |            **64 KiB** |
| 동시 프로세스/PID 수                  |                 **8** |
| 열린 파일 디스크립터                  |                **32** |
| 쓰기 가능한 임시 디스크 전체          |            **16 MiB** |

상한은 애플리케이션 코드의 사후 검사에만 의존하지 않고 샌드박스 경계에서 강제한다. 출력 상한에 도달하면 추가 출력을 버리고 실행을 종료한다. wall-clock, CPU, 메모리, 프로세스, FD, 디스크 상한을 넘긴 실행은 각각 구분 가능한 제한 초과 분류로 종료한다.

## Blocked resources

공개 베타 샌드박스에는 다음을 허용하지 않는다.

- 네트워크: 인터넷, 사설망, 루프백을 포함해 기본적으로 **전면 차단**
- 호스트 파일시스템: 호스트 경로 bind mount, 사용자 홈, 저장소, 소켓, 런타임 자격증명 접근 금지
- 영구 마운트: 데이터베이스 볼륨, 캐시, 사용자별 영구 디렉터리 금지
- 실행 간 상태 공유: 이전 실행의 파일·프로세스·IPC 상태 재사용 금지

컴파일러와 최소 실행 런타임은 읽기 전용 이미지 안에 제공한다. 학습자 작업 영역과 `/tmp`에 해당하는 쓰기 영역만 일회성으로 제공하고, 요청 종료 시 파일시스템·프로세스·IPC 상태를 모두 폐기한다.

## First-submit product contract

- 학습자는 실행 결과를 보기 전에 출력 예측 또는 답안을 **첫 제출**한다.
- 실행 버튼과 실행 결과는 첫 제출 이벤트가 확정된 뒤에만 활성화·표시한다.
- 실행 결과, 테스트 결과, 컴파일 오류는 교정 피드백일 뿐 최초 제출의 `correct`, `rating`, `firstSubmission` 또는 FSRS 등급을 수정하지 않는다.
- 실행 후 교정 제출을 별도 학습 이벤트로 남기는 경우에도 기존 첫 제출 이벤트를 덮어쓰지 않으며, 비-첫 제출 결과가 기억 일정을 다시 채점하는 근거가 되어서는 안 된다.

## Failure fallback

컴파일 오류, 런타임 오류, 샌드박스 내부 오류, 샌드박스 미가용, 제한 초과는 **학습자의 오답과 분리**한다.

- 실행 인프라 실패나 자원 제한 초과만으로 `correct: false`를 기록하지 않는다.
- 실행기가 실패해도 문제 풀이·설명·회상 흐름은 계속 사용할 수 있어야 한다.
- 가능한 경우 검수된 설명, 회상형 문항, 정적/수동 rubric 피드백으로 전환한다.
- 샌드박스 실패와 학습자 프로그램의 컴파일/런타임 실패는 서로 다른 분류로 표시한다.

## Event recording and retention

장기 이벤트와 `localStorage`에는 **실행 시도 메타데이터와 안전한 결과/실패 분류만** 남긴다. 허용되는 예시는 실행 시각, 콘텐츠 ID/버전, 컴파일/실행 단계, 샌드박스 정책 버전, 도구체인 버전, 아래와 같은 분류 코드다.

- `completed`
- `compile-error`
- `runtime-error`
- `wall-time-limit`
- `cpu-limit`
- `memory-limit`
- `output-limit`
- `process-limit`
- `fd-limit`
- `disk-limit`
- `sandbox-unavailable`
- `sandbox-error`

다음 데이터는 장기 이벤트, `localStorage`, 일반 애플리케이션 로그에 저장하지 않는다.

- 학습자가 제출한 C 소스 원문
- stdout/stderr 원문 또는 그 장기 복제본
- 학습자의 서술 답안·교정 답안 원문
- 샌드박스 내부 경로·환경변수·호스트 식별 정보처럼 공격 표면을 넓히는 상세 진단값

사용자에게 보여 주는 컴파일/실행 출력은 첫 제출 이후 현재 세션에서만 일시적으로 다루고, 장기 저장 계층으로 전달하지 않는다. 운영상 필요한 세부 장애 진단은 학습 이벤트와 분리된 개인정보·소스 비포함 집계로 제한한다.

## Implementation guardrails

C2 구현은 이 ADR이 **명시적으로 승인된 뒤** 별도 작업으로 시작한다. 최소한 다음 검증을 구현과 함께 추가해야 한다.

- 첫 제출 전 실행 버튼·실행 결과·기대 결과가 노출되지 않는 테스트
- 학습 이벤트와 `localStorage`에 C 소스, stdout/stderr 원문, 답안 원문이 저장되지 않는 테스트
- wall-clock/CPU/메모리/출력/프로세스/FD/디스크 제한 초과가 서로 안전한 분류로 종료되는 테스트
- 컴파일 오류, 런타임 오류, 샌드박스 장애와 제한 초과가 학습자 오답으로 기록되지 않는 테스트
- 실행기 실패 시 설명·회상·수동 rubric fallback으로 학습을 계속할 수 있는 테스트
- 공개 경계에서 네트워크, 호스트 파일시스템, 영구 마운트가 차단되고 실행 후 일회성 상태가 폐기되는 검증

보안 제한을 애플리케이션 레벨 플래그만으로 우회 가능하게 만들거나, 테스트 편의를 위해 공개 실행 경계를 느슨하게 해서는 안 된다.

## Consequences

- 공개 C 실행은 단순한 UI 기능보다 별도 샌드박스 운영 경계를 필요로 하므로 구현·관찰성·배포 비용이 증가한다.
- 짧은 시간·메모리·출력 제한 때문에 정상적이지만 큰 프로그램은 실패할 수 있다. 이는 현재 시험 코치의 짧은 연습 범위를 우선하는 의도된 제한이다.
- 실행 결과를 장기 저장하지 않으므로 사후 디버깅 정보가 줄어든다. 대신 학습자 소스·출력의 불필요한 보존과 정보 노출 위험을 줄인다.
- 샌드박스가 사용할 수 없을 때도 학습 흐름을 유지해야 하므로 실행 피드백은 코어 학습 계약의 보조 기능으로 남는다.

## Rejected alternatives

- **브라우저 전용 실행을 공개 보안 경계로 사용**: 브라우저 또는 같은 웹 애플리케이션 경계에 임의 C 실행 신뢰를 맡기지 않는다. 정적 예제에는 사용할 수 있어도 공개 임의 코드 실행의 승인 근거로는 부족하다.
- **애플리케이션 서버와 같은 프로세스/호스트에서 직접 컴파일·실행**: 컴파일러 공격면과 자원 고갈이 서비스·데이터 경계로 바로 이어지므로 거부한다.
- **네트워크가 열려 있거나 호스트 디렉터리를 마운트한 컨테이너**: 외부 공격·데이터 유출·지속성 경로를 남기므로 거부한다.
- **재사용 가능한 영구 샌드박스**: 실행 간 상태 오염과 교차 사용자 노출 위험 때문에 거부한다.
- **소스와 stdout/stderr를 장기 이벤트에 저장해 디버깅**: 기존 답안 원문 미저장 계약과 충돌하고 보존 위험이 커서 거부한다.
