# 현재 SQL 실행 엔진은 도입하지 않는다

정보처리기사 코치의 현재 SQL 수직 범위는 고정된 읽기 전용 dataset과 결과 행·열 동등성, 필수 절, 금지 토큰을 조합한 **결과 예측형 판정**으로 유지한다. 브라우저 WASM 또는 서버 SQL 엔진을 현재 MVP에 추가하지 않으며, 기존 `sql` 채점 계약과 `sql-employees-v1` 버전을 정식 학습 경로로 사용한다.

## 결정 이유

- 현재 5개 SQL 개념과 10개 검수 콘텐츠는 실제 실행 없이도 결과 예측·구문·조건 누락을 결정적으로 측정하며, 관련 catalog/grading 검증이 완료됐다.
- 브라우저 엔진은 SQLite 계열과 시험에서 기대하는 SQL 문법·오류 의미가 달라질 수 있고, WASM 의존성과 번들 크기를 추가한다.
- 서버 엔진은 학습자 SQL을 신뢰하지 않는 입력으로 취급해야 하므로 애플리케이션 DB와 분리된 임시 읽기 전용 실행 경계, 문장·행·시간·메모리 제한, 운영 관찰성이 필요하다. 현재 제품에는 이 운영 경계를 검증할 근거가 없다.
- 결과 예측형 판정은 답안 원문을 장기 저장하지 않고도 필요한 오류 유형과 학습 이벤트를 기록할 수 있다.

## 재검토 조건

실제 실행이 필요해질 경우 별도 ADR과 구현 작업으로 다룬다. 실행기는 애플리케이션 DB·자격증명·네트워크에 접근하지 않는 일회성 읽기 전용 dataset에서만 동작하고, 허용 dialect/문장 범위, 실행 시간·메모리·출력·행 수 상한, 실패 fallback, 답안 원문 비저장, 운영 계측을 먼저 검증해야 한다. 엔진을 사용할 수 없을 때도 현재 결과 예측형 학습 흐름을 유지한다.

## 결과

현재 작업에서는 새 SQL 실행 의존성, 서버 실행 route, 브라우저 실행기를 추가하지 않는다. SQL 실행 엔진 도입 여부 결정 작업은 이 ADR과 현재 현황 문서의 결정으로 완료한다.
