## 1. 제품 정의

정보처리기사 필기에 합격했지만 실기 준비의 시작점과 순서를 찾기 어려운 비전공자에게, 시험일까지 해야 할 **신규 학습·복습·실전 훈련의 우선순위**를 매일 안내하는 합격 코치다.

단순 문제은행이나 범용 암기 앱이 아니다. 공식 출제기준을 학습 가능한 경로로 바꾸고, 독립 회상 결과에 따라 기억 일정을 조정하며, 시간 제한 평가로 실전 전이를 확인하는 것이 제품의 핵심이다.

### 핵심 가치 제안

> 오늘 무엇을 얼마나 공부해야 하는지 고민하지 않고, 이해한 내용을 시험일까지 기억하고 실제 답안에 적용하게 한다.

### 해결할 문제

- 공식 출제 범위는 알 수 있지만 비전공자가 이해할 수 있는 선수지식과 학습 순서는 분명하지 않다.
- 읽기와 객관식 위주의 공부는 익숙함을 만들지만, 실기의 단답·SQL·코드 추론에 필요한 생성형 회상을 충분히 훈련하지 못한다.
- 복습량을 고정 주기로 운영하면 개인별 기억 차이와 시험일까지 남은 시간을 반영하기 어렵다.
- 진도율이나 연속 출석만으로는 실제 시험 준비 상태를 판단할 수 없다.
- 복원 문제에 의존하면 정확성·저작권·연도별 출제기준 대응에 지속적인 위험이 생긴다.

## 2. 공식 시험 기준

현재 기준은 Q-Net의 2026년 정보처리기사 출제기준이다. 실기는 `정보처리 실무`, 필답형 2시간 30분이며 100점 만점에 60점 이상이 합격 기준이다. 운영 전에는 반드시 해당 연도의 공식 출제기준과 일정을 다시 확인한다.

공식 실기 범위는 다음 12개 영역으로 관리한다.

1. 요구사항 확인
2. 데이터 입출력 구현
3. 통합 구현
4. 서버프로그램 구현
5. 인터페이스 구현
6. 화면 설계
7. 애플리케이션 테스트 관리
8. SQL 응용
9. 소프트웨어 개발 보안 구축
10. 프로그래밍 언어 활용
11. 응용 SW 기초 기술 활용
12. 제품 소프트웨어 패키징

공식 범위는 콘텐츠 누락을 확인하는 분류 체계이고, 학습 순서는 별도의 선수지식 그래프로 구성한다. 공식 목록의 나열 순서를 그대로 강의 순서로 사용하지 않는다.

### 공식 근거

- [Q-Net 정보처리기사 종목 상세정보](https://www.q-net.or.kr/crf005.do?id=crf00503&jmCd=1320)
- [Q-Net 출제기준 자료실](https://www.q-net.or.kr/cst006.do?code=1202&gSite=Q&id=cst00601)
- [Q-Net 가답안·확정답안 안내](https://q-net.or.kr/anc002.do?gSite=Q&id=anc00203)

Q-Net이 필답형 문제·답안을 일반적인 CBT 공개 문제처럼 제공하지 않는다는 전제에서, 서비스 문항은 공식 출제기준에 근거해 직접 작성한다. 비공식 복원 문제를 공식 기출처럼 수집하거나 표시하지 않는다.

## 3. 목표 사용자와 범위

### 핵심 학습자

- 정보처리기사 필기 합격자
- 실기 첫 응시를 준비하는 비전공자
- 하루 45~60분을 확보할 수 있지만 학습 순서 설계가 어려운 사람
- SQL이나 프로그래밍 언어를 문제에 적용하는 데 부담을 느끼는 사람

### 보조 사용자

- 실기 재응시자 중 취약 영역 진단과 복습 계획이 필요한 사람
- 긴 강의보다 짧은 능동학습과 실전 연습을 선호하는 사람

### 초기 비대상

- 필기 전 범위를 처음부터 공부하려는 수험생
- 자격증과 무관한 장기 개발 교육을 원하는 학습자
- 자유 형식 덱 제작이나 대규모 Anki 가져오기가 필요한 사용자
- 커뮤니티 경쟁, 랭킹, 강제 연속 출석을 원하는 사용자

## 4. 제품 목표와 비목표

### 목표

- 시험일과 하루 가용 시간에 맞춘 실행 가능한 계획을 제시한다.
- 이해 → 자유회상 → 적용 → 실전형 수행의 숙달 경로를 제공한다.
- 목표 기억률 90%를 기준으로 개인화된 복습 일정을 운영한다.
- 공식 12개 영역의 학습 범위와 현재 준비 상태를 근거와 함께 보여준다.
- SQL과 프로그래밍에서 첫 제출의 독립 수행 능력을 측정한다.
- 학습 콘텐츠의 정확성, 변경 이력, 권리 근거를 운영 가능하게 만든다.

### 비목표

- 진도율만으로 합격 확률을 산출하지 않는다.
- 1·3·7·14일과 같은 고정된 ‘에빙하우스 복습표’를 제공하지 않는다.
- AI가 정답 여부나 공식 해설을 최종 결정하지 않는다.
- 개인 검증 단계에서 전체 12개 영역을 얕게 채우지 않는다.
- 실제 기출처럼 보이는 비공식 복원 문제를 대량 수집하지 않는다.
- 초기 버전에서 결제, 소셜 랭킹, 공개 사용자 덱을 만들지 않는다.

## 5. Sentence에서 채용할 학습 원칙

Sentence의 콘텐츠나 기능을 복제하지 않고, 다음 상호작용 원칙만 이 제품의 문제에 맞게 채용한다.

| 채용 원칙                        | 이 제품에서의 적용                                            |
| -------------------------------- | ------------------------------------------------------------- |
| 제한된 오늘의 학습량             | 만기 복습과 계획된 신규·적용 활동을 시간 상한 안에서 제시     |
| 읽기보다 능동적 재구성           | 단답, 순서 배열, 코드 결과 예측, SQL 작성으로 직접 답 생성    |
| 답의 위치를 알려주는 즉시 피드백 | 잘못된 키워드·절차 단계·SQL 조건을 첫 제출 뒤 구체적으로 표시 |
| 점진적 도움                      | 개념 단서 → 구조 힌트 → 해설·정답 순서로 공개                 |
| 도움을 사용한 완료의 구분        | 학습 진도에는 반영하되 독립 회상 성공으로 기록하지 않음       |
| 재개와 재시도                    | 중단한 오늘 학습을 이어 하고, 교정 후 유사 문항으로 다시 회상 |
| 구조 스캐폴딩                    | 답안 틀, SQL 절 구조, 코드 추적 표 등 초보자용 발판 제공      |

채용하지 않는 것은 뉴스·문장이라는 콘텐츠 형식, 동일 서비스 안의 데이터 모델, 단순 완료 중심 성과 지표다.

## 6. 학습 설계

### 숙달 단계

각 개념은 다음 네 단계를 거친다.

1. **이해**: 예시와 반례를 통해 개념의 의미를 구분한다.
2. **자유회상**: 답이나 선택지를 보지 않고 핵심을 떠올린다.
3. **적용**: SQL, 코드, 절차, 사례에 개념을 사용한다.
4. **실전형 수행**: 시간 제한과 혼합 범위 안에서 답을 완성한다.

한 번 정답을 맞혔다고 숙달된 것으로 보지 않는다. 개별 회상 카드의 기억 상태와 여러 활동을 종합한 개념 숙달도를 분리한다.

### 5~10분 학습 단위

하나의 학습 단위는 다음 흐름으로 구성한다.

1. 개념 설명과 구체적 예시
2. 즉시 생성형 회상
3. 짧은 적용 문제
4. 첫 제출 채점과 교정
5. 필요한 경우 점진적 도움
6. 유사하지만 동일하지 않은 문제로 재회상

확인형 객관식·OX는 진단과 초기 이해 확인에는 쓸 수 있지만, 강한 기억 성공의 증거로 사용하지 않는다.

### 지식 유형별 학습 방식

| 지식 유형 | 기본 방식                         | 측정하는 신호                        | 피드백                              |
| --------- | --------------------------------- | ------------------------------------ | ----------------------------------- |
| 정의·용어 | 단답 자유회상, 빈칸               | 핵심어를 독립적으로 생성했는가       | 누락·혼동 키워드 표시               |
| 비교·분류 | 분류, 짝맞추기                    | 기준과 사례를 구분하는가             | 잘못 적용한 기준 설명               |
| 절차·순서 | 단계 배열, 빈 단계 채우기         | 순서와 선후 조건을 재구성하는가      | 첫 오류 지점과 원인 표시            |
| 코드      | 실행 결과 예측, 추적표, 짧은 작성 | 실행 없이 상태 변화를 추론하는가     | 첫 제출 후 제한 실행·테스트 피드백  |
| SQL       | 결과 예측, 절 완성, 쿼리 작성     | 요구 조건을 결과와 구문으로 옮기는가 | 결과 동등성과 필수 조건을 분리 채점 |
| 복합 사례 | 미니 사례형 단답                  | 여러 개념을 선택·결합하는가          | 채점 기준별 충족 여부 표시          |
| 실전 혼합 | 미니 테스트, 전체 모의고사        | 제한 시간 안에 전이되는가            | 종료 후 영역·오류 유형 분석         |

## 7. 핵심 사용자 흐름

### 7.1 시작과 진단

1. 계정 없이 바로 시작한다.
2. 시험 예정일과 평일·주말 학습 가능 시간을 입력한다.
3. 15~20분 진단으로 SQL, 프로그래밍, 필수 기초의 현재 상태를 추정한다.
4. 결과를 근거로 신규 학습량을 조정하되 단원을 영구 면제하지 않는다.
5. 남은 기간과 가용 시간에 맞춘 추천 경로를 생성한다.

8주는 내부 초기 권장값일 뿐 고정 상품명이 아니다. 기본 하루 학습량은 45~60분이며, 60분 기준 권장 배분은 만기 복습 15분, 신규 학습 25분, 적용 20분이다.

### 7.2 오늘 학습

홈 화면은 ‘오늘’이다. 큐는 다음 순서로 구성한다.

1. 기억 위험이 높은 만기 복습
2. 시험 중요도와 취약도가 높은 만기 복습
3. 오늘 계획된 신규 학습
4. 오늘 계획된 적용 활동

시간이 부족한 날의 최소 루틴은 만기 복습이다. 정해진 시간을 넘으면 모든 미완료 항목을 강제하지 않고, 남은 복습 부채와 신규 학습을 이후 일정에 다시 배치한다.

우선순위는 `공식 중요도 × 개인 취약도 × 시험 임박도`를 사용하되, FSRS의 개별 기억 상태 자체를 임의로 왜곡하지 않는다. 공식 가중치가 없는 경우 비공식 ‘기출 빈도’를 사실처럼 만들지 않는다.

### 7.3 정규 복습

1. 답을 보지 않고 첫 제출을 한다.
2. 시스템이 검수된 규칙으로 정오를 판정한다.
3. 오답은 `Again`으로 기록한다.
4. 정답인 경우에만 학습자가 체감 회상 난이도를 `Hard`, `Good`, `Easy`로 평가한다.
5. 힌트를 사용했다면 학습은 완료할 수 있으나 독립 회상은 실패로 처리한다.
6. 결과에 따라 다음 복습일을 계산한다.

### 7.4 취약점 훈련

다음 신호를 조합해 취약 개념을 추천한다.

- 반복되는 회상 실패
- 목표 기억률에 못 미치는 카드 집합
- 적용 문제의 동일 오류 유형
- 미니 테스트와 모의고사의 영역별 성과
- 긴 응답시간과 잦은 도움 사용

취약점 훈련은 만기 복습을 대신하지 않는다. 같은 정답을 외우게 하지 않도록 표현, 자료, 조건이 다른 독자 문항을 사용한다.

### 7.5 실전 훈련

- **미니 테스트**: 매주 20~30분, 최근 학습과 취약 영역을 혼합한다.
- **전체 모의고사**: 진도 50%, 80%, 시험 2주 전을 기준으로 150분 조건에서 시행한다.
- 평가 중에는 정답·힌트·실행 결과를 제공하지 않는다.
- 제출 또는 종료 후에 채점, 시간 배분, 영역별 약점, 다음 학습 권고를 제공한다.

실전 성과는 정규 복습의 기억 일정과 별도 상태로 저장한다. 모의고사 한 번의 오답이 카드의 FSRS 상태를 곧바로 덮어쓰지 않는다.

## 8. 기억 일정과 성과 모델

### FSRS 원칙

정규 복습은 유지되는 FSRS 구현을 사용한다. 카드별 난이도(Difficulty), 안정성(Stability), 회상 가능성(Retrievability)을 바탕으로 다음 복습일을 계산한다.

- 기본 목표 기억률은 90%다.
- `Again`은 실패이며, `Hard`는 힘들었지만 독립적으로 성공한 경우에만 선택한다.
- 목표 기억률을 지나치게 높이면 복습량이 급증하므로 개인 검증 중 임의로 상향하지 않는다.
- 알고리즘 버전, 파라미터, 목표 기억률을 상태와 함께 기록한다.
- 콘텐츠가 개정되면 의미가 같은 지식인지 검수한 뒤 기억 이력의 승계 여부를 정한다.

‘에빙하우스의 망각곡선’은 간격 반복의 배경 원리로 설명할 수 있지만, 한 사람의 기억 실험에서 나온 곡선을 모든 사용자에게 고정 복습표로 적용하지 않는다.

### 개념 숙달도

개념 숙달도는 다음을 별도로 보여준다.

- 이해 확인 여부
- 연결된 회상 카드의 현재 기억 상태
- 적용 문제 성과
- 실전형 평가 성과
- 도움 없이 해결한 최근 증거와 측정 시점

단일 퍼센트가 필요하더라도 세부 근거를 함께 노출하고, 이를 합격 확률이라고 부르지 않는다.

### 준비도 보고서

준비도 화면은 다음 구성요소를 제공한다.

- 공식 12개 영역의 학습 범위 커버리지
- 만기 복습 및 복습 부채
- 실제 회상률과 목표 기억률의 차이
- 영역별 개념 숙달도
- 최근 미니 테스트·모의고사 점수와 시간 추세
- 자주 발생하는 오류 유형
- 다음 7일의 예상 학습량과 위험 영역

## 9. 채점과 교정 정책

### 공통 원칙

- 정답 판정은 사람이 검수한 채점 규칙이 담당한다.
- 채점 규칙은 필수 키워드, 허용 표현, 결과 동등성, 테스트 조건을 포함할 수 있다.
- 첫 제출 이후의 수정은 교정 과정으로 기록하며 최초 독립 수행 결과를 바꾸지 않는다.
- AI는 추가 설명과 오답 원인 탐색에만 사용하며 권위 있는 채점자가 아니다.

### 코드

- 학습자는 코드를 실행하기 전에 결과 예측 또는 답안을 첫 제출한다.
- 첫 제출 이후에만 제한된 테스트 결과를 보여준다.
- 개인 검증에서는 범위를 제한한 로컬·서버 실행기를 사용할 수 있다.
- 공개 베타의 실행 환경은 네트워크 차단, 일회성 파일 시스템, 시간·CPU·메모리·출력 제한을 갖춘 격리 샌드박스여야 한다.

### SQL

- 읽기 전용 고정 데이터셋에서 실행한다.
- 결과 행·열의 동등성과 문제에서 요구한 필수 조건을 분리해 판정한다.
- 허용 가능한 복수 쿼리를 인정하고 문자열 완전 일치에 의존하지 않는다.
- 데이터 변경문이 필요한 학습은 트랜잭션 격리 또는 시뮬레이션으로 처리한다.

### 점진적 도움

도움은 독립 시도 이후에만 제공한다.

1. 개념 단서
2. 답안 구조 또는 첫 단계
3. 구체적 힌트
4. 해설과 정답

도움을 사용하면 학습 진행은 유지하지만 독립 회상 성공으로 기록하지 않는다. 이어서 조건이 다른 유사 문제를 배정해 다시 독립적으로 회상하게 한다.

## 11. 콘텐츠 체계와 운영

### 콘텐츠 원본

초기 콘텐츠는 Git에서 스키마 검증되는 Markdown/JSON으로 관리한다. 각 항목은 최소한 다음을 포함한다.

- 안정적인 콘텐츠 ID와 버전
- 공식 연도와 12개 영역 매핑
- 선수지식과 연결 개념
- 학습 목표와 지식 유형
- 문제, 정답, 해설, 채점 규칙
- 난이도와 예상 소요시간
- 작성자, 검수자, 검수 상태
- 출처·라이선스·권리 메모
- 변경 사유와 기억 이력 승계 결정

운영 규모가 커질 때 동일 스키마를 사용하는 관리자 UI를 추가한다. 운영 DB에서 조용히 직접 수정하지 않는다.

### 제작 및 공개 흐름

1. 공식 출제기준의 세부 항목을 학습 목표로 분해한다.
2. 개념과 선수지식 관계를 정의한다.
3. 사람이 독자 문항과 채점 규칙을 작성한다. AI 초안은 가능하다.
4. 별도 검수자가 정답, 해설, 범위 적합성, 허용 답안, 난이도를 확인한다.
5. 개인 초안은 개인 환경에서만 사용할 수 있다.
6. 공개 상태는 별도 검수 승인 후에만 부여한다.

### 오류 대응

신고된 문항은 우선 해당 버전을 출제 중지한다. 검수 결과에 따라 개정하거나 철회하고, 영향을 받은 학습자의 과거 이벤트는 삭제하지 않는다. 개정 버전이 같은 지식을 평가하지 않는다면 기존 카드 이력을 승계하지 않는다.

### 권리 원칙

- 공식 출제기준은 범위 근거로 연결하고 필요한 만큼만 요약한다.
- 타 교재 문항과 비공식 복원 문제를 변형해 자체 문항처럼 사용하지 않는다.
- 외부 도표·문장·데이터는 항목별 권리와 이용 조건을 기록한다.
- 공공누리 자료도 유형별 출처 표시, 상업 이용, 변경 허용 조건을 확인한다.
- [국가법령정보센터 저작권법](https://law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1030281869)과 [공공누리 이용 안내](https://www.kogl.or.kr/info/faqList.do?dataGroup=2&mstIdx=KOGL_005)를 운영 점검 기준으로 사용한다.

## 12. 계정, 개인정보, 동기화

### 계정 정책

- 게스트는 계정 없이 한 기기에서 시작할 수 있다.
- 장기 기록 보존과 여러 기기 동기화가 필요할 때 계정 연결을 제안한다.
- 게스트 기록은 계정 연결 시 명시적으로 이전한다.

### 최소 수집

장기 학습 이벤트에는 다음만 저장한다.

- 중복 방지 이벤트 ID와 발생 시각
- 사용자·콘텐츠·카드·콘텐츠 버전 ID
- 정오답과 `Again/Hard/Good/Easy`
- 응답시간, 도움 사용 단계, 학습 방식
- 첫 제출 여부와 평가 맥락
- 적용한 FSRS 버전

코드, SQL, 서술 답안 원문은 개인 오답 노트에 저장하기로 선택한 경우를 제외하고 장기 보존하지 않는다.

### AI 사용

- 사용자가 ‘AI 교정 요청’을 명시적으로 선택했을 때만 해당 답안을 외부 모델에 전송한다.
- 전송 전 제공자, 전송 데이터, 보존 정책을 알린다.
- 별도 동의 없이 모델 개선이나 다른 콘텐츠 제작에 답안을 재사용하지 않는다.
- AI 응답은 교정 피드백으로 표시하며 정답 판정을 변경하지 않는다.

### 오프라인과 충돌 해결

- 미리 내려받은 만기 복습과 짧은 학습 단위를 오프라인에서 수행할 수 있다.
- 각 결과는 중복 방지 ID가 있는 불변 학습 이벤트로 저장한다.
- 연결 후 서버가 이벤트를 중복 제거하고 발생 시각과 유효성을 확인한다.
- 마지막 상태나 최고 점수를 선택하지 않고 정식 이벤트 순서로 FSRS 상태를 재계산한다.
- 전체 오프라인 코드 실행은 초기 범위에서 제외한다.

## 13. 기술 방향

Sentence와 저장소, 배포, 사용자 데이터가 분리된 제품으로 만든다.

### 권장 구성

- 프런트엔드·서버: TypeScript, Next.js
- 앱 형태: 반응형 PWA, Service Worker, IndexedDB 오프라인 큐
- 데이터베이스: PostgreSQL
- 콘텐츠: 스키마 검증 Markdown/JSON, Git 버전 관리
- 기억 엔진: 유지보수되는 FSRS 구현을 어댑터 뒤에 고정
- 실행기: 개인 검증용 제한 실행기 → 공개 베타용 격리 샌드박스
- 분석: 식별 가능한 최소 학습 이벤트와 콘텐츠 품질 이벤트

- 학습 알림은 사용자가 시간과 요일을 직접 설정한다.

## 15. 성공 지표와 검증 기준

### 북극성 결과

실전형 평가 점수와 제한 시간 내 수행 능력이 개선되는가.

### 선행 지표

- 7일 이상 지연된 독립 회상 성과
- 실제 회상률과 목표 90% 사이의 보정 오차
- SQL·C 문제의 첫 제출 정답률과 응답시간 추세
- 공식 범위별 이해 → 회상 → 적용 증거의 커버리지
- 복습 부채의 크기와 회복 가능성

### 개인 검증 완료 조건

8주 동안 다음을 함께 확인한다.

- 최소 6주 이상 계획을 실제로 수행했다.
- 월간 실제 회상률이 목표 90% 근처에서 안정적으로 보정된다.
- 7일 지연 회상 성과가 기준선보다 개선된다.
- SQL과 C의 시간 제한 평가 점수 또는 같은 점수까지 걸린 시간이 개선된다.
- 학습을 막는 중대한 콘텐츠 오류가 0건이다.
- 복습 부채가 일상적으로 감당 가능한 수준에서 회복된다.

실제 시험 합격은 이후의 강한 결과 증거이지 개인 검증을 시작하기 위한 조건은 아니다.

### 공개 베타 진입 조건

- 공식 12개 영역 각각에 최소 학습 경로가 있다.
- 모든 공개 콘텐츠에 공식 범위 연결과 별도 검수 기록이 있다.
- Java와 Python을 포함한 공식 언어 학습 경로가 마련돼 있다.
- 계정·동기화·개인정보 삭제 흐름이 검증됐다.
- 공개 코드 실행기가 격리·제한·관찰 가능하다.
- 핵심 흐름이 WCAG 2.2 AA 수준의 접근성 검증을 통과했다.
