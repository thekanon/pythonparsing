# 정보처리기사 실기 합격 코치 실행 로드맵

- 기준일: 2026-09-01
- 전제: 1인 사이드 프로젝트
- 구축 기간: 12~16주
- 개인 검증: 구축 후 8주
- 최초 수직 범위: SQL, C 언어

관련 문서: [제품 기획서](./information-processing-practical-coach.md) · [도메인 용어집](../../CONTEXT.md)

## 1. 일정 해석

12~~16주는 제품을 개인 학습에 사용할 수 있게 만드는 **구축 기간**이다. 기억 유지와 실전 전이는 시간이 지나야 측정할 수 있으므로, 구축 완료 뒤 별도 8주 개인 검증을 진행한다. 최초 판단까지의 총 기간은 약 20~~24주다.

빠른 전체 목차 채우기보다 SQL과 C에서 ‘설명 → 회상 → 적용 → 실전 평가’가 끝까지 작동하는 수직 범위를 먼저 만든다.

## 2. 단계별 구축 계획

### 1~2주: 기준선과 콘텐츠 기반

**목표**: 잘못된 범위와 데이터 구조 위에서 개발을 시작하지 않는다.

- 해당 연도 Q-Net 실기 출제기준 원본과 변경 이력 확보
- 공식 12개 영역 식별자와 세부 목표 초안 작성
- SQL·C의 선수지식 그래프와 최초 학습 경로 정의
- 콘텐츠 Markdown/JSON 스키마와 검증 명령 작성
- 콘텐츠 ID, 버전, 채점 규칙, 검수 상태, 권리 메타데이터 정의
- 학습 이벤트와 FSRS 어댑터의 계약 테스트 설계
- 기준선 평가용 SQL·C 진단 및 미니 테스트 작성

**완료 조건**

- SQL·C의 모든 최초 콘텐츠가 공식 범위 항목에 연결된다.
- 잘못된 콘텐츠 파일이 CI에서 거부된다.
- 진단과 8주 후 평가에 사용할 동형 평가 세트가 준비된다.

### 3~5주: 학습 엔진과 게스트 PWA

**목표**: 계정 없이 학습하고 기억 이력을 남길 수 있다.

- Next.js PWA 기본 구조와 반응형 셸 구현
- 게스트 식별과 로컬 학습 이력 저장
- 이해 자료, 생성형 회상, 적용 활동 렌더러
- 첫 제출, 즉시 교정, 점진적 도움 흐름
- `Again/Hard/Good/Easy` 입력 규칙과 설명
- FSRS 목표 기억률 90%, 버전 고정, 다음 복습 계산
- 중복 방지 ID가 있는 불변 학습 이벤트 저장
- 카드 기억 상태와 개념 숙달도 분리

**완료 조건**

- 오답과 힌트 사용이 성공으로 기록되지 않는다.
- 동일 이벤트 재전송이 기억 상태를 중복 변경하지 않는다.
- 학습 단위 한 개를 모바일과 데스크톱에서 끝낼 수 있다.

### 6~8주: SQL 수직 범위

**목표**: SQL을 기초에서 실전형 수행까지 학습한다.

- 고정 읽기 전용 데이터셋과 문제별 초기화
- 결과 예측, 절 완성, 쿼리 작성 방식
- 결과 행·열 동등성 판정
- 필수 조건과 금지 조건을 포함한 채점 규칙
- 첫 제출 후 실행과 오류 교정
- 조건이 다른 유사 문항 재회상
- SQL 진단, 주간 미니 테스트, 취약점 분류

**완료 조건**

- 문자열이 다른 동등 쿼리를 허용한다.
- 첫 제출 전 실행 결과를 볼 수 없다.
- 오답이 구문, 조건 누락, 조인, 집계 등 교정 가능한 유형으로 분류된다.

### 9~11주: C 언어 수직 범위

**목표**: C의 기초 개념을 코드 추적과 짧은 작성으로 연결한다.

- 변수·연산·제어 흐름·배열·포인터 등 공식 범위 기반 경로
- 실행 결과 예측, 상태 추적표, 빈 코드, 짧은 작성 방식
- 첫 제출 이후 제한된 컴파일·테스트 결과
- 시간·메모리·출력 상한과 위험한 기능 차단
- C 진단, 주간 미니 테스트, 취약점 분류
- Java·Python 확장을 위한 언어 중립 인터페이스 확인

**완료 조건**

- 실행 없이 예측한 첫 답과 실행 후 수정 답이 구분된다.
- 코드·컴파일 출력이 장기 학습 이벤트에 불필요하게 저장되지 않는다.
- 핵심 흐름이 실행기 장애 시에도 설명·회상 모드로 계속 동작한다.

### 12~13주: 오늘, 계획, 준비도

**목표**: 사용자가 매일 다음 행동을 스스로 설계하지 않아도 된다.

- 시험일, 가용 시간, 진단에 따른 목표일 계획
- 만기 복습 우선의 시간 제한 오늘 큐
- 복습 부채와 신규 학습 자동 조절
- `공식 중요도 × 취약도 × 시험 임박도` 우선순위
- 오늘/커리큘럼/취약점/모의고사/리포트 정보 구조
- 커버리지, 실제 회상률, 숙달 증거, 점수·시간 추세
- 사용자 설정 학습 알림과 Q-Net 확인 링크

**완료 조건**

- 15분, 45분, 60분 시간 예산에서 큐가 예측 가능하게 종료된다.
- 놓친 날 이후 복구 계획이 생기고 전체 부채를 한 번에 강제하지 않는다.
- 준비도 어디에도 근거 없는 합격 확률이 표시되지 않는다.

### 14주: 오프라인과 동기화 기반

**목표**: 연결이 불안정해도 만기 복습을 잃지 않는다.

- Service Worker와 IndexedDB 다운로드·큐
- 만기 복습과 짧은 학습 단위 오프라인 수행
- 재연결 시 이벤트 중복 제거와 유효성 검사
- 시간순 이벤트 재생과 FSRS 상태 재계산
- 충돌·시계 오차·부분 업로드 테스트

**완료 조건**

- 동일 이벤트의 반복 업로드 결과가 멱등적이다.
- 두 기기의 성공·실패 기록이 모두 보존된다.
- 마지막 쓰기나 최고 점수로 기억 상태를 덮어쓰지 않는다.

### 15~16주: 안정화와 개인 검증 준비

**목표**: 8주 동안 실제 공부에 의존할 수 있는 상태를 만든다.

- 키보드, 터치, 스크린리더 핵심 흐름 점검
- 모바일 복습과 데스크톱 SQL·코드 작업 사용성 개선
- 콘텐츠 오류 신고, 출제 중지, 개정 버전 처리
- 백업·복구와 데이터 내보내기 확인
- 학습 이벤트·성공 지표 대시보드
- 개인정보 고지와 AI 교정 요청 동의 흐름
- 기준선 평가 실시 및 8주 계획 고정

**완료 조건: 개인 MVP 게이트**

- SQL·C 수직 범위가 기초부터 미니 테스트까지 연결된다.
- 목표 기억률 90%의 기억 일정과 오늘 큐가 안정적으로 동작한다.
- 중대한 콘텐츠 오류와 데이터 손실 경로가 없다.
- 개인 검증 지표를 수집하되 답안 원문은 기본 장기 저장하지 않는다.

12주로 단축해야 한다면 14~16주의 오프라인·접근성·운영 자동화를 축소하고 수동 검증으로 대체한다. FSRS 평가 규칙, 첫 제출, 콘텐츠 검수, 데이터 무결성은 축소하지 않는다.

## 3. 구축 후 8주 개인 검증

### 검증 질문

- 실제 회상률이 목표 90% 부근으로 보정되는가?
- 7일 이상 지난 내용을 도움 없이 더 잘 회상하는가?
- SQL과 C의 시간 제한 문제 성과가 개선되는가?
- 하루 시간 상한 안에서 복습 부채를 감당할 수 있는가?
- 콘텐츠 오류가 학습 신뢰를 깨뜨리지 않는가?

### 측정 설계

**시작 전**

- SQL·C 동형 기준선 평가
- 영역별 첫 제출 정답률과 응답시간 기록
- 하루 가용 시간과 시험일 확정

**매일**

- 계획 대비 실제 세션 수행
- 만기 복습 수, 완료 수, 남은 부채
- 첫 제출 결과, 회상 평가, 응답시간, 도움 사용
- 실행기·동기화·콘텐츠 오류

**매주**

- 20~30분 미니 테스트
- 7일 이상 지연 회상 코호트
- 목표 기억률 보정과 영역별 취약점 검토
- 다음 주 신규 학습량 조절

**4주차**

- 중간 동형 평가
- 지나친 복습량, 잘못된 카드 분할, 채점 규칙 문제 수정
- 콘텐츠가 바뀌면 버전과 이력 승계 결정을 기록

**8주차**

- 종료 동형 평가
- 기준선 대비 점수·시간·지연 회상 비교
- 실제 회상률과 목표 기억률 차이 분석
- 복습 부채의 중앙값·최댓값·회복시간 분석
- 다음 단계 진입 여부 결정

### 통과 기준

- 8주 중 6주 이상 계획 실행
- 월간 실제 회상률이 90% 근처에서 안정
- 7일 지연 회상이 기준선보다 개선
- SQL·C 평가 점수 상승 또는 같은 점수까지의 시간 단축
- 학습을 막는 중대한 콘텐츠 오류 0건
- 반복적으로 회복 불가능한 복습 부채가 없음

어느 하나의 숫자만으로 통과시키지 않는다. 기억 유지와 실전 전이가 함께 개선되고, 운영 부담이 지속 가능해야 한다.

## 4. 비공개 파일럿

개인 검증 통과 후 소수의 비전공 초시생을 초대한다.

- 게스트 시작과 선택적 계정 연결 검증
- 서로 다른 시험일·학습시간에서 계획 품질 확인
- `Again/Hard/Good/Easy` 오사용과 힌트 정책 이해도 관찰
- 개인별 FSRS 보정과 복습 부채 분포 확인
- SQL·C 채점의 허용 답안 누락 수집
- 정답·해설 신고에 대한 중지·개정 처리시간 측정

파일럿 콘텐츠는 개인 초안과 분리하고, 공개 가능한 항목은 작성자 외 검수자의 승인을 받는다.

## 5. 공개 베타 확장

공개 베타는 기능 완성보다 콘텐츠·보안·운영 게이트를 기준으로 연다.

### 필수 확장

- Java, Python 학습 경로와 코드 추적 방식
- 공식 12개 영역별 최소 이해·회상·적용 경로
- 모든 공개 문항의 공식 범위 연결과 별도 검수
- 연도별 출제기준 차이 검토와 콘텐츠 영향 분석
- 계정, 기기 간 동기화, 내보내기·삭제
- 공개용 격리 코드 실행 샌드박스
- 장애·오류 신고·출제 중지·개정 운영 화면
- WCAG 2.2 AA 접근성 검증
- 개인정보 처리와 외부 AI 전송 고지

### 공개 베타 게이트

- 12개 공식 영역에 빈 학습 경로가 없다.
- 미검수·권리 불명 콘텐츠가 공개 큐에 들어가지 않는다.
- 콘텐츠 오류가 보고되면 즉시 해당 버전을 출제 중지할 수 있다.
- 악성 코드가 네트워크·호스트 파일·다른 실행에 접근하지 못한다.
- 여러 기기의 오프라인 이벤트가 손실 없이 합쳐진다.
- 핵심 학습 흐름을 마우스 없이, 소리 없이, 스크린리더로 완료할 수 있다.

## 6. 우선순위 원칙

일정이 밀릴 때 다음 순서로 보호한다.

1. 정답·해설과 공식 범위의 정확성
2. 첫 제출과 기억 일정의 신뢰성
3. 학습 이벤트 무결성과 복구 가능성
4. 오늘 큐와 복습 부채의 지속 가능성
5. SQL·C 실전 전이 측정
6. 접근성과 핵심 기기 사용성
7. 편의 기능과 시각적 완성도

범위를 줄일 때는 콘텐츠 수, 부가 리포트, 알림 자동화를 먼저 줄인다. 정확성·개인정보·샌드박스 안전 기준을 일정과 교환하지 않는다.
